# Title

Safe ZIP entry iterator with resource caps

## Summary

Implement `src/importers/archive.ts`: a yauzl-based async iterator over ZIP entries with the
DESIGN.md §6.3 safety caps (entry count, per-entry and total uncompressed size, compression
ratio, encrypted/nested detection), streaming entries to consumers without ever writing to
disk. This is the T4/T5 security boundary for all imports.

## Context

Export archives are untrusted input (threat table B2). Parsers must receive plain readable
streams and never see archive internals; all archive risk is concentrated and tested here.

## Scope

- `src/importers/archive.ts` + unit tests with crafted fixture zips (committed under
  `fixtures/archives/`, generated by a checked-in script `fixtures/archives/make.ts` so they
  are reproducible).
- Add dependency `yauzl` (+ `@types/yauzl` dev).

## Detailed Requirements

1. API:
   ```ts
   interface ArchiveEntry { name: string; uncompressedSize: number;
                            open(): Promise<NodeJS.ReadableStream>; }
   interface ArchiveCaps { maxEntries: number; maxEntryBytes: number;
                           maxTotalBytes: number; bombRatio: number; bombMinBytes: number; }
   export const DEFAULT_ARCHIVE_CAPS: ArchiveCaps = {
     maxEntries: 10_000, maxEntryBytes: 2 * 2**30, maxTotalBytes: 6 * 2**30,
     bombRatio: 1_200, bombMinBytes: 10 * 2**20 };   // exactly DESIGN §6.3
   async function* iterateZipEntries(filePath: string, options?: {
     caps?: Partial<ArchiveCaps>;
     onSkip?: (name: string, reason: 'directory' | 'nested_zip') => void;
   }): AsyncGenerator<ArchiveEntry>;
   ```
2. Behavior:
   - `yauzl.open` with `{ lazyEntries: true, autoClose: false, validateEntrySizes: true }`.
   - Entry **names are data only**: never used to touch the filesystem; yielded unchanged
     (no normalization) even for hostile names (`../evil.json`, `/abs/path.json`,
     `C:\evil.json`) — T5. Directory entries (name ends `/`) are skipped without yielding;
     `onSkip(name, 'directory')` is called.
   - Encrypted entry (general purpose bit 0) → throw `AppError('ERR_ARCHIVE_ENCRYPTED')`.
   - Entry count over cap → `ERR_ARCHIVE_BOMB` (details: `{ reason: 'entries' }`).
   - Declared `uncompressedSize` over per-entry cap, or running total over total cap →
     `ERR_ARCHIVE_BOMB` (`reason: 'size'`).
   - Ratio check: if `uncompressedSize / max(compressedSize,1) > bombRatio` AND
     `uncompressedSize > bombMinBytes` → `ERR_ARCHIVE_BOMB` (`reason: 'ratio'`).
   - **Enforced during streaming too**: wrap the entry stream in a counting transform that
     aborts with `ERR_ARCHIVE_BOMB` if actual bytes exceed declared `uncompressedSize` + 1 KiB
     slack or the caps (declared sizes can lie even with `validateEntrySizes`).
   - Nested archive entries (name matching `/\.zip$/i`) are skipped without yielding an
     `ArchiveEntry`; `onSkip(name, 'nested_zip')` is called.
   - Error precedence (both levels tested): counting-transform cap violations map to
     `ERR_ARCHIVE_BOMB`; every other yauzl/open/entry-stream error (open failure, corrupt
     central directory, mid-stream read error) maps to `ERR_ARCHIVE_CORRUPT` with the
     original message in `details` — including errors surfacing on the entry stream after
     `open()` resolved.
   - The generator owns cleanup: `finally { zipfile.close() }`; abandoning the iterator midway
     must not leak file descriptors (test with `process.getActiveResourcesInfo()` or fd count
     on POSIX).
3. Fixture script creates: normal zip (3 small files), encrypted-entry zip, 10,001-entry zip
   (tiny entries; generation must stay < 5 s), high-ratio bomb (zeros, e.g. 20 MiB → ~20 KiB),
   lying-header zip (patched central directory declaring smaller size than actual — construct
   by writing raw bytes; if impractical with yauzl-toolchain, construct with `yazl` devDep and
   binary patching), nested zip, corrupt zip (truncated), and a hostile-names zip containing
   entries named `../evil.json`, `/abs/path.json`, `C:\evil.json`, `a/../../b.json`.

## Acceptance Criteria

- [ ] Happy path: yields all file entries with working streams whose content matches fixtures.
- [ ] Each crafted fixture triggers exactly its specified `AppError` code/reason.
- [ ] Streaming over-read (lying header) aborts mid-stream with `ERR_ARCHIVE_BOMB`;
      mid-stream corruption surfaces as `ERR_ARCHIVE_CORRUPT` (precedence tested).
- [ ] Hostile-names zip: names yielded verbatim as data; no filesystem API touched beyond
      opening the original zip path (fs spy); nothing normalized or resolved.
- [ ] Directory + nested-zip entries skipped; `onSkip` invoked with exact reasons
      `'directory'` / `'nested_zip'`.
- [ ] No fd leak after early `break` from the iterator (asserted).
- [ ] No disk writes anywhere in the module (code review + no `fs.write` usage).

## Validation

`npm test` (suite `src/importers/archive.test.ts`), lint, typecheck. Fixtures are committed;
`make.ts` is provided for manual regeneration and is not run in pretest.

## Dependencies

## Non-goals

(zip only in v1 — Takeout tgz option is documented as unsupported; users must choose zip).
